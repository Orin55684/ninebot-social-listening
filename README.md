# 九号电动智能舆情分析预警系统

本项目面向九号电动社媒与用户社群，建设统一的舆情分析和风险预警能力。第一期统一规划社媒与社群的数据结构和事件口径，优先落地社群模块。

当前阶段为项目定义与方案评审，不开展生产数据接入或自动化分析。项目文档中的“拟定”内容需要业务负责人确认后方可冻结。

## 当前结论

- 第一期分析约 500 个企微官方用户群和约 50 个民间微信群。
- 当前消息量约 45 万条每周，历史数据可回溯半年并支持增量获取。
- 第一期只分析文字消息，不处理图片、语音和视频内容。
- 重大风险的目标发现与通知时限为 2 小时。
- 告警由售后服务运营团队人工确认和决定升级，通过飞书通知。
- 处理结论需要回流系统，第一期不建设完整工单闭环。
- 允许用稳定的匿名用户 ID 关联同一用户的不同时段或跨群消息。
- 原始文本和脱敏文本均不得发送给外部模型；生产分析只能使用公司批准并私有部署的模型。
- 开发阶段暂接个人 DeepSeek API，但仅允许使用模拟或公开数据；代码层会拒绝生产社群数据。
- 正式服务器为 2 核 CPU、2 GB 内存和 40 GB 云硬盘。该服务器不承担大模型推理，模型应由公司的独立推理服务提供。
- 社媒数据源暂时预留接口，等待确认公司 VOC 系统的数据导出能力。

## 项目阶段

当前处于“需求冻结与开发框架准备”阶段。可使用模拟或公开数据验证 DeepSeek 模型适配器；真实社群数据接入前仍需确认公司模型的程序化调用方式、微伴助手接口字段、飞书通知方式和数据保留规则。

## 开发验证

当前代码只包含可替换模型网关，不包含真实数据采集或分析任务。无需真实 API Key 即可运行单元测试：

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

需要手工验证 DeepSeek 时，在本地环境变量中配置 `DEEPSEEK_API_KEY`。不要把密钥写入仓库，也不要使用真实社群消息作为测试输入。
