# 九号电动智能舆情分析预警系统项目章程

版本：0.1  
状态：可进入评审  
范围：总体框架与社群一期

## 项目背景

九号电动的用户反馈分散在抖音、小红书、快手、B 站、企微官方用户群和民间微信群中。社群消息密度高、上下文强，依赖人工巡群难以及时识别集中故障、安全风险和跨群扩散，也难以持续沉淀用户需求及产品洞察。

项目将建立统一的数据口径、问题分类、事件聚合和预警机制。第一期优先验证社群端到端链路，并为社媒或 VOC 数据接入预留标准接口。

## 项目目标

业务目标按当前优先级排列：

1. 识别产品故障、质量问题和集中投诉。
2. 汇总用户需求与产品建议。
3. 提升社群客服和运营效率。
4. 发现潜在公关危机并提前预警。
5. 为管理层提供周期性报告。
6. 形成品牌口碑及竞品洞察。
7. 评估新品、活动和传播内容的反馈。

第一期的核心成功标志不是功能数量，而是用真实数据跑通“数据进入、问题识别、事件聚合、人工确认、飞书通知、结果回流”的完整闭环。

## 一期范围

### 纳入范围

- 约 500 个企微官方用户群和约 50 个持续活跃的民间微信群。
- 微伴助手过去半年历史消息及后续增量消息。
- 文字消息、群聊上下文、时间、群、匿名用户和消息关联关系。
- 产品问题分类、集中投诉识别、安全风险候选识别和事件摘要。
- 2 小时重大风险预警、日级热点报告和周月级洞察。
- 售后服务运营团队人工确认、飞书通知和处理结论回流。
- 为社媒或 VOC 数据预留统一事件接口。

### 不纳入一期

- 图片文字识别、语音转写、视频内容理解和附件内容分析。
- 自动创建工单、跨部门任务流和处理时效考核。
- 自动对外回复用户或直接采取公关行动。
- 社媒与社群的跨平台事件合并。
- 使用外部大模型或腾讯云公共模型服务处理真实社群数据。DeepSeek 仅可用于模拟或公开数据的开发验证。
- 在 2 核 2 GB 服务器上部署大模型推理服务。

## 约束

- 原始消息和脱敏后的消息均不得发送到外部模型。
- 个人 DeepSeek API 仅作为开发适配器，不改变真实数据的安全边界。
- 模型和数据必须运行在公司认可的私有环境中。
- 当前公司尚无明确的大模型、数据安全及个人信息处理规范，需要在试运行前补充最低管理规则。
- 正式应用服务器资源有限，需要采用轻量架构，并将模型推理放在公司已有的独立服务上。
- 当前没有专职产品、研发、算法或数据人员，方案必须降低部署与维护复杂度。

## 前置依赖

1. 公司模型是否提供程序化 API，而不只是 Cherry Studio 或 WorkBuddy 中的交互入口。
2. 微伴助手 API 的正式文档、鉴权、限流、增量游标和字段说明。
3. 飞书机器人或应用的通知权限。
4. 腾讯云环境是否被公司认定为合规的私有运行环境。
5. 文本及分析结果的数据保留、备份和删除规则。
6. VOC 系统是否支持社媒数据导出，以及能够提供哪些字段。

## 阶段出口

本阶段在总体 PRD、一期范围、安全边界、风险口径、模型接入清单和验收方法完成业务评审后结束。未解决的技术依赖可以进入待办台账，但不得被默认视为已经具备。
