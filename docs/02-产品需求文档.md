# 九号电动智能舆情分析预警系统产品需求文档

版本：0.1  
状态：评审稿  
一期重点：社群文本分析

## 产品定义

系统持续接收官方企微群和民间微信群的文字消息，对单条反馈进行结构化识别，将相似反馈聚合为事件，结合问题严重度、消息增速和传播范围生成风险候选。售后服务运营团队在系统中完成确认，通过飞书接收需要升级的告警，并把处理结论回流供后续分析与评估。

系统不替代业务人员做最终风险决策，也不自动对外发布信息。

## 用户与核心任务

### 售后服务运营团队

- 查看新增高风险候选及证据。
- 判断是否属于真实故障、重复投诉、集中事件或误报。
- 决定风险等级及是否通过飞书升级。
- 填写处理结论和误报原因。

### 用户运营团队

- 查看日级群聊热点、用户诉求和异常趋势。
- 查询问题涉及的群、车型、时间和匿名用户范围。
- 汇总高频需求、运营问题和用户建议。
- 参与分类口径及系统效果评估。

### VOC团队及管理层

- 接收周期性汇总。
- 查看问题趋势、重点车型、集中投诉和处置结论。
- 后续接入社媒数据后查看跨渠道事件。

## 典型业务流程

1. 系统从微伴助手获取历史或增量文字消息。
2. 系统完成格式统一、敏感字段处理和稳定匿名用户 ID 生成。
3. 系统识别车型、部件、问题、情绪、诉求和潜在安全信号。
4. 系统将相似消息聚合为同一事件，并计算消息数量、增速、群覆盖和用户覆盖。
5. 系统综合严重度、传播、趋势和模型置信度形成风险候选。
6. 售后服务运营团队查看摘要及必要证据，确认或驳回候选。
7. 需要升级的事件通过飞书通知相关人员，目标是在符合预警条件后的 2 小时内完成通知。
8. 业务人员将最终分类、风险等级、处理结论和误报原因回流系统。
9. 系统生成日级热点及周月级洞察。

## 功能需求

### 数据接入

| 编号 | 需求 | 一期验收要点 |
| --- | --- | --- |
| FR-001 | 接入微伴助手半年历史及增量消息 | 可记录同步范围、时间和失败原因，重复同步不产生重复消息 |
| FR-002 | 统一官方群与民间群字段 | 每条消息具有来源、群、匿名用户、时间、类型和来源消息标识 |
| FR-003 | 保留文字上下文关系 | 可还原同一时间窗口内的对话，并尽可能保留引用或回复关系 |
| FR-004 | 预留VOC或社媒导入接口 | 在无真实社媒数据时仍有明确字段契约，不影响社群模块运行 |

### 隐私与身份

| 编号 | 需求 | 一期验收要点 |
| --- | --- | --- |
| FR-010 | 对手机号等直接身份信息脱敏 | 分析页面及模型输入不出现受控敏感字段 |
| FR-011 | 生成稳定匿名用户ID | 同一来源中的同一用户可持续关联，无法由普通使用者反推真实身份 |
| FR-012 | 限制原文访问 | 只有获授权角色可查看必要原文，其他角色查看摘要和脱敏证据 |
| FR-013 | 记录敏感操作 | 原文查看、数据导出和权限变更具有审计记录 |

### 分析与事件

| 编号 | 需求 | 一期验收要点 |
| --- | --- | --- |
| FR-020 | 识别车型、部件和问题分类 | 支持一期分类树，并保留“其他/待确认” |
| FR-021 | 识别用户意图 | 区分故障反馈、投诉、咨询、建议、转述和无关讨论 |
| FR-022 | 识别安全风险线索 | 少量但高严重度的信息不会被纯消息量规则淹没 |
| FR-023 | 聚合相似消息为事件 | 同一问题的重复消息尽量合并，不同车型或故障原因可拆分 |
| FR-024 | 计算事件趋势 | 展示消息量、用户数、群数、增速和时间分布 |
| FR-025 | 生成可核验摘要 | 摘要包含事实、影响范围、代表性证据和不确定项，不编造未出现的信息 |

### 预警与人工确认

| 编号 | 需求 | 一期验收要点 |
| --- | --- | --- |
| FR-030 | 生成风险候选 | 每个候选展示触发原因及评分组成 |
| FR-031 | 支持人工确认与驳回 | 记录操作者、时间、结论和原因 |
| FR-032 | 支持风险等级调整 | 业务人员可覆盖系统建议，覆盖记录可追溯 |
| FR-033 | 通过飞书发送告警 | 告警包含事件摘要、风险等级、影响范围、触发原因和查看入口 |
| FR-034 | 满足2小时预警目标 | 对满足约定条件的重大风险，从首个有效信号到通知不超过2小时 |
| FR-035 | 回流处理结论 | 记录确认分类、最终风险、业务结论和误报原因，供评估及后续优化 |

### 报告与检索

| 编号 | 需求 | 一期验收要点 |
| --- | --- | --- |
| FR-040 | 生成日级热点报告 | 展示新增风险、问题排行、异常上升、主要车型及待确认事件 |
| FR-041 | 生成周月级洞察 | 展示长期趋势、用户需求、产品建议、服务问题和已处理事件 |
| FR-042 | 按条件检索 | 支持按时间、群、车型、分类、风险等级和状态筛选 |
| FR-043 | 查看事件演化 | 展示事件首次出现、峰值、扩散和处理结论 |

## 非功能需求

### 安全

- 生产数据不得进入外部模型、外部日志、外部分析工具或公共调试服务。
- 模型调用只允许指向公司批准的私有推理服务。
- 个人 DeepSeek API 仅用于模拟或公开数据的开发验证，不得接收真实社群消息或其脱敏版本。
- 凭证不得写入代码或普通配置文档。
- 原文访问采用最小权限原则，数据导出默认关闭。
- 备份、日志和临时文件适用相同的数据安全要求。

### 性能与容量

- 当前平均消息量约 45 万条每周，即约 6.4 万条每日；系统应支持热点期间的明显增长。
- 增量同步、规则筛选和事件聚合应持续运行，不能依赖每天一次的全量批处理来满足 2 小时目标。
- 2 核 2 GB 应用服务器不得承担本地大模型加载与推理。
- 40 GB 磁盘能否覆盖半年消息、索引、日志、备份和分析结果，需要基于实际数据抽样测算；在测算前列为容量风险。
- 一期不下载或长期保存图片、音视频等大体积附件，除非后续另行批准。

### 可维护性

- 采用单体优先、模块隔离的轻量设计，避免引入需要专人维护的复杂分布式组件。
- 数据源、模型和通知渠道均通过适配层隔离，便于替换供应方或接口。
- 所有关键任务具有运行状态、错误记录和人工重试能力。

## 数据输出契约

社群和未来 VOC 或社媒数据最终都转换为统一的“内容记录”和“事件记录”。至少包含：

- 数据来源和来源内容标识。
- 内容发生时间、采集时间和群或频道标识。
- 稳定匿名用户标识。
- 脱敏文字及受控原文引用。
- 车型、部件、问题、意图和情绪标签。
- 事件标识、风险等级、置信度和触发原因。
- 人工确认状态、最终结论和更新时间。

## 一期退出条件

- 历史及增量数据链路能够稳定运行。
- 公司模型可被程序化调用，且数据不离开批准环境。
- 一批人工标注样本能够完成端到端评估。
- 重大风险候选能够在 2 小时目标内到达人工确认及飞书通知环节。
- 每日热点报告能够生成并被业务人员理解。
- 误报、漏报和处理结论可以回流并追溯。
