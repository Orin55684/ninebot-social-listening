# 公司模型接入确认清单

版本：0.2
用途：向公司IT 模型平台或 WorkBuddy 负责人确认程序化调用条件

## 当前判断

公司模型已经通过开发机上的程序化 API 与合成数据测试，确认服务可达、目标模型存在，并能返回结构化 JSON。该结果只证明技术可行，不等同于生产审批；专用服务账号、服务器网络、日志留存、限流和真实数据授权仍需由公司负责人确认。

## 已验证信息（2026-09-14）

| 项目 | 结果 |
| --- | --- |
| API 基址 | 已验证；内网地址只保存在本地或部署密钥配置中，不写入公开仓库 |
| 接口兼容性 | OpenAI 兼容的模型列表与 Chat Completions |
| 测试模型 | `deepseek-v4-flash-0731` |
| 开发机网络 | 连接公司 VPN 后，模型列表及调用可达 |
| 鉴权 | API Key 鉴权成功；密钥未进入仓库 |
| 结构化输出 | `response_format=json_object` 测试成功 |
| 测试数据 | 仅使用明确标注的合成文本 |

以上测试未验证生产服务器网络、正式服务账号、并发与限流、长上下文、故障恢复及服务端数据留存。

## 必须确认的信息

| 类别 | 需要确认的问题 | 影响 |
| --- | --- | --- |
| 接口 | 是否提供服务端API；接口协议和文档地址是什么 | 决定能否自动调用 |
| 地址 | 内网访问地址、端口、TLS要求和网络白名单 | 决定服务器能否连接 |
| 模型 | 正式模型名称、版本和模型标识 | 决定请求参数及效果基线 |
| 鉴权 | API Key、令牌、账号或其他鉴权方式；如何申请及轮换 | 决定凭证管理 |
| 权限 | 当前 Cherry Studio 或 WorkBuddy 权限能否申请为系统服务账号 | 决定生产授权主体 |
| 限流 | 每分钟请求数、并发数、日配额和超限行为 | 决定批处理和队列策略 |
| 输入 | 最大上下文长度、单次最大输入、支持的中文长度 | 决定群聊上下文组装 |
| 输出 | 是否支持严格JSON或结构化输出；是否支持固定随机性 | 决定结果稳定性与解析方式 |
| 能力 | 是否另有向量或Embedding模型；是否允许批量调用 | 决定事件聚合方法 |
| 隐私 | 服务端是否记录提示词、输入和输出；日志保留多久、谁可访问 | 决定是否满足数据边界 |
| 可用性 | 服务可用时间、超时、重试规则和维护通知 | 决定运行保障 |
| 费用 | 是否计费、如何分配额度和查看用量 | 决定运行预算 |

## 建议发给内部负责人的询问文本

我们正在建设一个私有部署的社群舆情分析系统，生产消息不得发送到外部模型。当前员工可以在 Cherry Studio 和 WorkBuddy 中使用公司部署的模型，现需确认该模型是否提供经过公司批准的服务端 API，供腾讯云私有应用程序调用。请提供接口协议、内网地址、模型标识、鉴权申请方式、网络要求、限流与并发、上下文长度、结构化 JSON 输出能力，以及输入输出日志和数据保留策略。如果现有权限仅供交互式客户端使用，也请说明是否能够申请系统服务账号。

## 接入验证通过标准

- 正式服务器能够在批准网络路径中访问模型服务。
- 使用专用服务凭证，不依赖个人客户端登录态。
- 输入输出不会被发送到第三方或用于未经批准的训练。
- 能稳定返回机器可解析的结构化结果。
- 限流和延迟能够支撑约 45 万条每周消息经过筛选后的分析负载。
- 模型不可用时，系统可以暂存任务、降级为规则识别并在恢复后重试。

## 未获得API时的处理

如果公司只提供 Cherry Studio 或 WorkBuddy 的人工交互入口，则不能把界面自动化当作正式模型接口。此时可以继续完成 PRD、数据接入、脱敏、规则筛选、事件结构和离线测试框架，但生产自动分析应保持阻塞，直至取得正式 API 或公司批准的替代方案。
