## 公司分类体系

读取用户提供的《业务标签.xlsx》，只保留产品线为“通用”或产品线列表包含“电动”的 766 个叶标签；跨产品线共享的电动标签仍适用。排除仅 SPS、仅短交通等不包含上述范围的标签。

保留四级路径、四级描述、主责部门、领域标签和原产品线。七个一级分类为 APP、产品、服务、销售、营销、物流、企业口碑。领域标签与产品线是不同字段，不以“领域标签”筛选通用或电动。

当前每条消息最多匹配一个公司主标签，方式为词面规则，明确标为“待核实”。未匹配消息保留“未分类”，不编造完整分类结果。该分类与原模型 topic、风险等级、人工核验分别保存。此次规则匹配 39,528 条；其余 1,045,282 条为未分类。标签体系可完整浏览，点击标签可查看对应消息。

## 查看真实原始数据

打开风险事件的“查看原文”，直接看到完整原始文字、原始引用、真实群名、渠道、平台和来源字段。所有 1,084,810 条已导入消息均有原始记录映射。

- 企微：原消息 ID、群 ID/名称、发送者 ID/名称、原时间戳、记录定位等。
- 微信 JSONL：真实群名及完整原 JSON 字段，包括引用信息；MD 补充记录保留原文、作者、时间及来源文件。
- VOC：真实平台及完整 CSV 原始列。评论不拼接其他评论作为上下文。
- 意见建议：原 XLSX 的反馈、受理、处理和评价字段。

模型判断区单独显示模型结果及模型分析时的预处理上下文。它们不代替原文。原始长消息不再按 1,500 字截断：已补齐的原文最大 4,520 字，8 条超过原有截断长度。

人工确认、驳回和核验依据仍写入独立核验数据库；新增未分析候选必须由操作人员明确选择最终等级。本次验证只对隔离合成数据提交核验，原人工核验记录未变。

## 数据浏览及筛选导出

进入“数据浏览”，选择日期、消息来源、渠道、话题、分类标签或关键词，点击“应用筛选”。

- 日期按上海时区日历日处理，包含开始和结束当天。此演示只提供 2026 年 8 月。
- “消息来源”为四个业务来源；“渠道”保留企业微信、微信、九号出行APP及 VOC 四个平台。
- “话题”为公司一级标签或未分类；“分类标签”为公司四级路径。
- 关键词可匹配原文、引用及原始记录字段。
- 每页 30 条，完整记录可展开查看。
- CSV / JSON 导出当前**已应用筛选**的所有记录，不限于当前页。修改表单后需再次应用，避免导出条件与页面结果不一致。
- CSV 带 UTF-8 BOM，可用 Excel 打开；源文本有公式前缀时添加文本转义。JSON 保留原值，用于无损交换。
- 大文件由服务端分批导出、浏览器原生下载，不在页面内一次缓存全部数据。

## 专项报告与周期模拟

进入“报告中心”，填写标题、周期与筛选条件，点击“生成专项报告”。也可以在数据浏览中点击“用此筛选生成报告”。

报告包含筛选范围、来源汇总、公司话题分布、周期统计及带来源定位的原文摘录。区分消息总量、分析成功、未分析、其他分析状态、成功分析的 R1–R3 风险记录；不把消息数量当作事件数，不以少量模型样本外推总体风险比例。

支持日报、周报、月报、自定义周期。周报按周一至周日划分，并裁切至所选日期范围；八月全月因此产生六个窗口（8月1–2日、3–9日、10–16日、17–23日、24–30日、31日）。

填写自动报告名称并保存周期配置后，点击“模拟运行”。系统读取四个来源的本地历史数据，依次记录模拟获取、整合、筛选及逐周期产出状态，生成并保存多份报告。来源读取失败会标记失败或部分完成，不把未知数量写成零。

**这是用户触发的历史调度模拟**，不是已连接真实接口或已启动后台定时调度。公司模型、采集服务及通知服务不会因此被调用。

报告可导出 HTML 或 JSON。HTML 可在浏览器打开后打印、存储为 PDF。已生成文件位于本地忽略目录 `data/august-demo/exports/`，报告中心已有“四来源充电体验专项周报（八月回放）”的配置和成功运行记录。

## 运行与存储

本地服务：

```sh
PYTHONPATH=src python3.11 scripts/august_server.py \
  --snapshot data/august-demo/snapshot.json \
  --state data/august-demo/local-reviews.db \
  --assets design-samples/dist --port 8882
```

原始记录与公司标签保存在回放库，报表查询以只读连接访问。人工核验仍保存在 `local-reviews.db`；周期配置和报告独立保存在 `local-reviews-reports.db`。源文件、回放库及含原文导出不进入公开代码仓库。

增量导入意见建议和标签：

```sh
PYTHONPATH=src python3.11 scripts/august_replay.py import \
  --taxonomy /本机/业务标签.xlsx --suggestions /本机/意见建议文件夹
PYTHONPATH=src python3.11 scripts/august_replay.py export
```

为旧消息重新补齐原文时，增加 `--refresh-originals` 并提供旧来源路径；不会修改源文件或已有分析 ID。导入标签后，如需重新匹配所有旧消息，应同时重新读取旧来源。微信导入仍需 `--wecom` 提供官方群排除依据。

模型分析命令继续要求 `--approve-historical-demo`；扩展来源后只补入此前样本计划未覆盖的新来源，不重复分析已成功样本。不自动运行此命令。

本轮验证：43 项测试通过；真实计数核对、所有原文映射覆盖核对、企微已分析证据原文与作者比对、筛选完整导出、报告汇总、六周期模拟及桌面/窄屏界面检查。此次本地查询测得全量分页汇总约 0.17 秒，月报生成约 4.73 秒；性能为本机验证值。

## 全量模型分析的批量运行

`scripts/analyze_suggestions_all.py` 仅调用已配置的公司模型，跳过已成功记录，包含意见建议来源全部记录（不受候选关键词门槛影响）。支持 `--rpm`（上限60）、`--batch-size`（上限10）、`--workers`（上限8）；由统一调度器控制请求间隔与滚动60秒窗口。每批反馈独立判断，输出ID必须与输入精确对应，所有字段通过校验后才逐条保存。字段异常拆为单条重试；429等待至少60秒并降低频率；每条最多尝试3次，失败可再次运行续接。状态及吞吐指标保存在本地 `suggestions-analysis-status.json`，每两分钟更新页面快照。

实测30和20 RPM均出现HTTP429，不能将标称30–50 RPM视为当前账号的已验证可用额度；批量请求也可能受到共享配额或令牌限制。该结果不改变人工核验要求。

使用新 key 后，`--probe-rpm` 从指定档位每次增加10 RPM，最高60，每档至少观察90秒且成功请求数至少达到该档RPM数值。全局请求间隔和滚动60秒计数双重限流，重试也计入；出现429就停止升档并回退、冷却。实测通过仅代表当前负载下可用，不代表服务正式配额上限。

新key实测：30/40/50/60 RPM配置分别观察至少90秒，四档均未触发429；60档实际滚动请求量约54–57次/分钟，单次最多8条。全量任务保持60 RPM上限续跑，失败校验结果拆分重试，不计为已成功分析。实验记录保存于本地 `suggestions-rpm-probe.json`。
