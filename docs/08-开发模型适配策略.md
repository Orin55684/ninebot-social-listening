# 开发模型适配策略

版本：0.1  
状态：已建立基础适配器

## 临时策略

在公司私有模型 API 尚未确认期间，开发阶段使用个人 DeepSeek API 验证提示词、JSON 结构和模型网关。DeepSeek 只处理模拟数据或公开数据，不处理任何官方企微群、民间微信群、微伴助手导出数据及其脱敏版本。

## 为什么必须限制数据

DeepSeek API 属于项目私有环境之外的服务。此前已经确认原始消息和脱敏消息均不得发送给外部模型，因此临时接入不能自动改变生产数据安全边界。若未来确需使用真实数据，必须由公司数据责任人明确批准并同步修改安全决策。

## 适配层设计

业务模块只依赖统一的模型网关，不直接依赖 DeepSeek：

- `ModelRequest` 强制携带数据分类。
- `DeepSeekGateway` 只允许 `synthetic` 和 `public`。
- `production_chat` 和 `company_approved` 在网络调用前被拒绝。
- 密钥只从 `DEEPSEEK_API_KEY` 环境变量读取。
- 模型输出统一转换为 JSON 对象。
- 后续增加公司私有模型适配器时，业务分类、事件和预警逻辑保持不变。

## 当前默认配置

- 接口地址：`https://api.deepseek.com/chat/completions`
- 模型：`deepseek-flash`
- 输出：JSON object
- 思考模式：关闭，以便控制延迟和输出结构
- 调用方式：非流式

具体配置通过本地环境变量覆盖，不将真实密钥提交到版本库。

## 后续切换条件

取得公司模型的服务端 API 地址、服务凭证、模型标识、结构化输出能力和网络策略后，实现公司私有适配器，并把 `MODEL_PROVIDER` 切换到该适配器。切换前需用同一批人工标注样本比较输出质量。
