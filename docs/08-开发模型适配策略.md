# 开发模型适配策略

版本：0.2
状态：已建立双模型适配器

## 当前策略

公司私有模型 API 已通过开发机上的合成数据验证，项目新增 `company_private` 适配器作为正式方向。个人 DeepSeek 保留为开发备用通道，只处理模拟数据或公开数据，不处理任何官方企微群、民间微信群、微伴助手导出数据及其脱敏版本。

## 为什么必须限制数据

DeepSeek API 属于项目私有环境之外的服务。此前已经确认原始消息和脱敏消息均不得发送给外部模型，因此临时接入不能自动改变生产数据安全边界。若未来确需使用真实数据，必须由公司数据责任人明确批准并同步修改安全决策。

## 适配层设计

业务模块只依赖统一的模型网关，不直接依赖 DeepSeek：

- `ModelRequest` 强制携带数据分类。
- `DeepSeekGateway` 只允许 `synthetic` 和 `public`。
- `CompanyPrivateGateway` 默认只允许 `synthetic` 和 `public`。
- `company_approved` 和 `production_chat` 默认都在网络调用前被拒绝；完成生产治理确认后才能通过显式配置开启。
- 密钥只从 `DEEPSEEK_API_KEY` 环境变量读取。
- 公司模型密钥只从 `COMPANY_MODEL_API_KEY` 环境变量读取。
- 模型输出统一转换为 JSON 对象。
- 两个供应方共用 OpenAI 兼容协议实现，业务分类、事件和预警逻辑不依赖具体模型。

## 公司模型配置

- Provider：`company_private`
- 接口基址：通过本地或部署环境变量提供，不写入公开仓库
- 模型：`deepseek-v4-flash-0731`
- 输出：JSON object
- 思考模式：关闭
- 调用方式：非流式
- 生产群聊：默认关闭

## DeepSeek 备用配置

- 接口地址：`https://api.deepseek.com/chat/completions`
- 模型：`deepseek-flash`
- 输出：JSON object
- 思考模式：关闭，以便控制延迟和输出结构
- 调用方式：非流式

具体配置通过本地环境变量覆盖，不将真实密钥提交到版本库。

## 生产开启条件

使用专用服务凭证，并确认生产服务器网络、服务端输入输出日志、数据保留、限流和真实社群数据授权后，才能把 `COMPANY_MODEL_ALLOW_PRODUCTION_DATA` 设为 `true`。开启前还需用同一批人工标注样本比较个人 DeepSeek 开发结果与公司模型结果，但不得把真实或脱敏社群文本发送给个人 DeepSeek。
