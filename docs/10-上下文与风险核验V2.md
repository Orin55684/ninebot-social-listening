# 上下文与风险核验 V2

本轮目标：补足单条关键词分析的上下文与证据类型，降低安全词导致的误报，提供可核查的同类问题线索。

## 运行

沿用社群历史回放命令，默认数据目录改为 `data/demo-v2/`，默认本地端口改为 8766。

```bash
PYTHONPATH=src python3.11 scripts/community_demo.py import --wecom /本机/企微.db --wechat /本机/微信JSONL目录
PYTHONPATH=src python3.11 scripts/community_demo.py analyze --approve-historical-demo --limit 12 --request-interval 15
PYTHONPATH=src python3.11 scripts/community_demo.py report
PYTHONPATH=src python3.11 scripts/community_demo.py serve
```

V1 数据和人工反馈保留在旧目录，V2 需独立数据库；分析器拒绝在已有 V1 成功分析的库上混跑。默认端口变化后，不会中断已有的 V1 页面。

## 分析变化

- 微信 JSONL 支持 `quote` 类型，作者回复与引用原话分开保存和脱敏；引用中的安全词可以使消息进入候选池。
- 每次调用仍以一条目标消息为单位，同时提供同来源同群、前后各 5 分钟内最多 8 条邻近消息。按照时间距离取最近消息，再按时间排序。只能使用导入样本中存在的上下文，不能保证连续完整。
- 仅关联微信导出自带的引用文本；不尝试凭昵称或时间重建缺失引用，也尚未解析企微原始嵌套引用载荷。
- 模型必须区分亲历反馈、转述、咨询、建议、否认、玩笑或无法判断，并返回具体问题、明确车型、置信度与判断依据。
- 安全词只影响初筛和优先级，不再直接覆盖模型等级。咨询、建议、否认、玩笑统一为 R4；R1 还需要亲历/转述以及明确安全反馈标志。证据不足的 R1 降为 R3 待人工核验，保留模型原等级和校验说明。
- 置信度是模型自评，不是经过标注校准的准确概率；本轮不以它触发通知。
- 本机保留每次分析实际使用的脱敏上下文快照，页面可展开查看。

## 候选与跨群线索

同一来源、群、日期、主题、具体问题、车型形成候选组。相比 V1，明确不同问题或不同车型不会再合并。依然不是完整的语义事件识别；同一天同群同车型同问题可能是不同个体事件，未知车型的归并也要人工核验。

疑似跨群同类问题仅纳入 R1–R3 的亲历/转述反馈，要求明确车型和同一具体问题，且出现于至少两个来源内群标识。跨来源群映射尚未完成，因此不宣称真实独立群数，不认定传播，也不自动升级。它是整个演示窗口的关联，暂未配置滚动时间窗口或车型别名归一化。

## 样本趋势的边界

页面显示每天、每来源的导入数、候选数、已分析数及 R1–R3 反馈数。当前每群/每来源限量导入，又是风险优先分析，不具有可比的历史基线。因此明确显示“样本不足以判定异常增长”，不计算整体投诉增长率，也不启用趋势告警。

后续若要启用异常增长识别，需导入连续可比窗口，固定群范围，统计有效用户及去重事件，以人工标注验证基线和触发条件。

所有通知仍需要人工确认，且仅写本地模拟通知箱。上下文包含目标之后的信息，仅适用于历史回看，不能据此宣称实时两小时发现能力。
