# 2026-09-16 生产同步

## 发布内容

液态玻璃界面、四来源历史数据、原始证据、通用与电动标签、筛选导出、统计报告和专项模型报告。专项链接和导出兼容 `/listening-private/` 子目录。

GitHub 仅保存代码、模板、测试及说明；历史消息数据库、报告产物、登录凭证、模型密钥和部署包均不提交。UI 原为嵌套仓库，原 Git 元数据保留在本机忽略目录 `data/deploy-20260916/design-samples.git`，本次将 UI 源码统一纳入主仓库。

## 生产布局

- 应用：`/opt/ninebot-listening-august`，使用与仓库相同的 `src/`、`scripts/`、`design-samples/dist/` 布局。
- 数据：应用目录内只读 `replay.db`、`snapshot.json`，由本机 SQLite 一致性备份产生。
- 人工核验：`/var/lib/ninebot-listening-august/reviews.db`，保留服务器原记录。
- 报告：上述状态目录内 `reviews-reports.db`、`topic-reports/`。首次同步已有专项报告样品与缓存，后续不得覆盖线上新增状态。
- 入口保留原 HTTPS 登录保护，应用仅监听回环地址 8881。
- 服务账号仅可写状态目录，不可写代码与源数据。

## 模型连接限制

本次检测生产服务器无法连接公司模型接口（TCP 超时）。本机 VPN 不会覆盖云服务器；未将本机模型密钥上传。已生成报告可查看和导出，统计报表使用本地数据，无需模型。线上新专项报告需先由公司提供服务器可用的网络路径，再在应用根目录配置仅服务账号可读的 `.env.local`（或 systemd 环境文件），使用 `COMPANY_MODEL_*` 配置。不得改用外部公共模型处理真实数据。

周期报告目前仍为用户触发的八月历史模拟，不代表定时任务或实时渠道接口已接入。

## 回退

切换前将旧应用及服务配置备份至 `/opt/ninebot-listening-backups/20260916/`，并备份独立状态目录。回退应用时停止服务、恢复旧应用目录和 unit、reload 后启动；人工核验状态默认保留现状，不能直接用旧备份覆盖新产生的记录。

## 验证

本地 Python 3.11 与服务器 Python 3.10 均通过 52 项测试；项目最低版本声明同步为已验证的 3.10。

生产服务通过 `COMPANY_MODEL_DISABLED_REASON` 提示内网连接尚未打通，阻止创建注定失败的模型任务；网络和凭证配置完成后移除该环境变量并重启服务。已生成报告与统计导出不受影响。

最终验证：本地 53 项测试通过；服务器原有 52 项全套测试通过，新增网络不可用保护连同专项模块 7 项测试通过。生产数据库 quick_check 为 ok，四来源共 1,084,810 条原始记录。HTTPS 登录校验、私有文件 404、来源查询、报告 HTML/JSON 与筛选 CSV 导出通过；对比备份确认 reviews/history/simulated_outbox 内容未变。启用 JSON、JS、CSS、CSV 的 gzip 压缩，改善大快照传输。Nginx 原配置同存于上述备份目录的 nginx-location.conf。
