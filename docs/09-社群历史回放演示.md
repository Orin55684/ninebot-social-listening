# 社群历史回放演示

项目定位更新：公司内部 AI 使用比赛，以历史数据跑通企微与微信导出两类来源。社媒暂缓，生产上线不是本轮目标。

## 使用方式

在 Python 3.11+ 环境中，从项目根目录运行。数据库和所有演示产物均在 Git 忽略的 `data/` 内。

```bash
PYTHONPATH=src python3.11 scripts/community_demo.py import --wecom /本机/企微.db --wechat /本机/微信JSONL目录
PYTHONPATH=src python3.11 scripts/community_demo.py analyze --approve-historical-demo --limit 24
PYTHONPATH=src python3.11 scripts/community_demo.py report
PYTHONPATH=src python3.11 scripts/community_demo.py serve
```

打开 `http://127.0.0.1:8765` 查看候选、脱敏证据和每日概览；确认或驳回后反馈保存在本地数据库。确认 R1/R2 生成模拟通知记录，不调用飞书，不对外发送消息。

模型调用需要公司内网或 VPN，以及本机 `.env.local` 中的公司模型地址与密钥。历史演示必须显式传入批准参数，只在本次调用中允许内部历史样本；持久化的生产数据开关保持关闭。无外部模型回退。连续两次分析失败即停止本轮，已完成分析保留，下次运行可续跑。报告显示失败数，失败不计入成功分析。

实测公司接口会返回 HTTP 429 限流。默认调用间隔为 12 秒，可用 `--request-interval 15` 降低请求频率；失败记录保留错误类型及 HTTP 状态，不保存响应体或密钥。再次运行会优先按风险与历史时间选择未完成消息，包括失败重试。

## 当前抽样与处理口径

- 默认窗口为北京时间 2026-08-21 00:00 至 2026-08-28 00:00，结束边界不包含。
- 每个来源最多导入 3000 条，每群最多 50 条；企微按时间取样，微信按文件遍历取样。不是随机或代表性样本。
- 企微通过员工与会话联合键关联会话表，只导入群聊文字。微信本轮优先使用 JSONL 的文字类型；Markdown、引用消息与多媒体留待后续。
- 消息按来源、群标识和原始消息 ID 去重。群与用户标识通过带本地随机盐的 HMAC 替代，不保存原昵称。
- 微信昵称只能支撑群内关联，同名用户仍可能误合并；导出来源不自动等同于民间群，官方/民间归属需后续映射。
- 身份信息处理包括常见手机、邮箱、链接、身份证号与显式身份标签。自由文本中的姓名、详细住址及间接身份信息不能保证完全删除，脱敏结果仍为内部数据。
- 先用关键词选择候选，再在两个来源间交替取样调用模型。安全红线命中优先处理，保守设为 R1 待核验；关键词只是演示筛选器，不能视作有效的事故判断。
- 模型输入是单条消息，缺少上下文。按同来源、同群、同日、同主题形成候选组，尚未实现完整语义事件聚合或跨群传播识别。
- 每日概览来自已分析抽样，不能估算全量投诉率、风险趋势、模型准确率或两小时发现时效。
- 历史时间排序用于导入和候选处理；尚未实现按可调倍速持续注入的流式回放。

## 演示与生产的区别

本轮有真实的历史导入、公司模型调用、结果存储、浏览页、人工反馈和模拟通知。真实微伴增量、飞书发送、访问权限管理、后台队列、生产容量及稳定性验证不在本轮实现范围。SQLite 源文件仅以只读方式访问，演示库另建。

公开代码仓库禁止提交演示数据库、包含历史证据的 HTML 报告、公司内网地址和凭据。报告只在本机生成与查看。
