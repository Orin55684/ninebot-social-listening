# 验收与项目推进

版本：0.1  
原则：先跑通安全可控的完整链路，再逐步提高模型效果

## MVP最低成果

1. 能够同步一段历史消息并持续获取增量文字消息。
2. 能够完成去重、脱敏和稳定匿名用户关联。
3. 能够通过公司模型接口输出问题分类、风险线索和事件摘要。
4. 能够将相似反馈聚合为事件并展示变化趋势。
5. 售后团队能够确认或驳回风险候选并调整等级。
6. 符合条件的事件能够通过飞书通知。
7. 人工处理结论和误报原因能够回流。
8. 能够生成可阅读的每日热点报告。

## 样本与标注

- 从历史消息中抽取覆盖普通讨论、高频问题、集中投诉和潜在安全问题的样本。
- 森森与 Orin 负责业务标注和分歧讨论。
- 标注至少包含问题主题、车型或部件、用户意图、是否形成事件、风险等级和是否应预警。
- 重大安全类样本即使数量少也必须单独覆盖，不能只做随机抽样。
- 公司赛事组织方按端到端可用性验收项目成果。

## 观测指标

试运行阶段先建立基线，不在缺少样本时承诺没有依据的目标数值。

| 指标 | 定义 |
| --- | --- |
| 重大风险召回率 | 人工认定应预警的事件中，系统成功形成候选的比例 |
| 告警准确率 | 系统发送的告警中，人工确认有效的比例 |
| 误报量 | 每日或每周需要人工驳回的候选数量 |
| 发现时效 | 首个有效信号到形成候选、人工确认和飞书通知的时间 |
| 分类准确率 | 问题主题及风险等级与人工标注一致的比例 |
| 事件聚合质量 | 相同事件被正确合并、不同事件未被错误合并的程度 |
| 巡群时间节省 | 业务人员试运行前后的人工巡检时间变化 |
| 洞察采纳量 | 被售后、运营或VOC采用的有效洞察数量 |

## 推进阶段

### 阶段一 需求与依赖冻结

- 评审当前 PRD、范围、安全边界和风险分类。
- 指定技术运行负责人。
- 取得微伴助手、公司模型和飞书接口资料。
- 确认数据保留、备份和原文权限规则。

### 阶段二 数据与模型可行性验证

- 只读核对现有 SQLite 数据结构和数据量。
- 验证微伴助手历史及增量接口。
- 验证公司模型的程序化调用、结构化输出、延迟和限流。
- 估算半年文本、索引、日志和备份所需空间。

### 阶段三 离线历史回放

- 建立人工标注样本。
- 验证分类、聚合、风险候选和摘要。
- 根据误报与漏报调整分类和触发规则。
- 确定试运行使用的风险阈值。

### 阶段四 小范围试运行

- 先选择部分群静默运行，不发送正式告警。
- 业务团队核对候选及报告。
- 通过后开启飞书告警，再逐步扩大覆盖范围。

### 阶段五 一期验收

- 使用约定样本和真实试运行记录评估指标。
- 验证数据没有离开批准环境。
- 完成运行说明、备份恢复和故障处理交接。

## 暂不设置固定日期的处理

项目当前没有专职产品、研发、算法或数据人员，也不要求复杂排期。因此采用阶段出口管理：上一阶段的必要条件满足后再进入下一阶段。任何阶段都不得以“先运行再补安全条件”为由绕过模型授权或数据边界。
